# EXP 4: CI/CD Pipeline and Prompt-based Automation (GitHub Actions + Gemini)

**Aim:** To build a GitHub Actions pipeline that tests the scripts on every push, updates the Agile task with pass/fail status, and uses a prompt-based script (LLM) to summarise the monitoring log, detect issues and share the report.

**Needs:** SETUP (including the Gemini key), EXP2 Steps 1–2 (repo pushed), and **Issue #1** on GitHub (EXP3 Step 1).
> If Issue #1 doesn't exist yet, run:
> `gh issue create --repo tejuthomass/oss-lab-exam --title "Automate system monitoring with cron (monitor.sh)" --body "Tracking issue"`

**Pipeline flow:** push → **test** (`bash -n` on every `.sh` file) → if it passes: **report** (AI report, artifact, comment PASSED on Issue #1); if it fails: **failed** (comment FAILED on Issue #1).

## Step 2: Prompt-based report script
```bash
nano exp4/ai_report.py
```
```python
#!/usr/bin/env python3
# Prompt-based report: summarises the monitoring log and detects issues
import os, json, subprocess, urllib.request

LOG_FILE = "exp1/system_monitor.log"
REPORT = "exp4/report.md"
MODELS = ["gemini-3.1-flash-lite", "gemini-3.5-flash-lite", "gemini-2.5-flash"]

# 1. Read the data (log tail, or live values if the log is empty)
data = ""
if os.path.exists(LOG_FILE):
    data = open(LOG_FILE).read()[-1500:]
if data.strip() == "":
    data = subprocess.getoutput("date; df -h /; free -h")

# 2. Build the prompt
prompt = ("You are a DevOps assistant. Read this system monitoring log and write a short report "
          "with exactly two sections:\n"
          "## Summary - one paragraph on overall system health.\n"
          "## Issues Detected - bullet list of errors or resource problems "
          "(disk above 80%, high memory, no swap). If none, write 'No issues detected.'\n\n"
          "Log:\n" + data)

# 3. Ask Gemini (try each model in turn)
key = os.environ.get("GEMINI_API_KEY", "")
answer = None
for model in MODELS:
    if key == "":
        break
    try:
        url = "https://generativelanguage.googleapis.com/v1beta/models/" + model + ":generateContent"
        body = json.dumps({"contents": [{"parts": [{"text": prompt}]}]}).encode()
        req = urllib.request.Request(url, data=body, headers={"Content-Type": "application/json", "x-goog-api-key": key})
        result = json.loads(urllib.request.urlopen(req, timeout=60).read())
        answer = result["candidates"][0]["content"]["parts"][0]["text"]
        print("Report generated by", model)
        break
    except Exception as e:
        print(model, "failed:", e)

# 4. Fallback if the AI is not reachable
if answer is None:
    answer = "## Summary\nAI not reachable, rule-based check used.\n\n## Issues Detected\n"
    found = False
    for word in data.split():
        if word.endswith("%") and word[:-1].isdigit() and int(word[:-1]) >= 80:
            answer += "- Disk usage is high: " + word + "\n"
            found = True
            break
    if not found:
        answer += "- No issues detected.\n"

# 5. Save the report
with open(REPORT, "w") as f:
    f.write("# Automated System Report\n\n" + answer + "\n")
print(open(REPORT).read())
```
Test it on your machine (run from `~/oss_lab`):
```bash
cd ~/oss_lab
export GEMINI_API_KEY=$(cat ~/.gemini_key)
python3 exp4/ai_report.py
```
✅ It prints "Report generated by gemini-..." and a report with **Summary** and **Issues Detected**. The report is saved in `exp4/report.md`.

**Prompt design (write in exam):** a **role** ("You are a DevOps assistant"), a fixed **output format** (two sections), a **rule for the empty case** ("If none, write No issues detected"), and **limited input** (last 1500 characters of the log).

## Step 4: The CI/CD pipeline file
```bash
nano .github/workflows/ci.yml
```
```yaml
name: CI Pipeline

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  issues: write

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Check syntax of all shell scripts
        run: |
          for f in $(find . -name "*.sh"); do
            echo "Checking $f"
            bash -n "$f"
          done

  report:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Generate AI report
        env:
          GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}
        run: python3 exp4/ai_report.py
      - name: Save report as artifact
        uses: actions/upload-artifact@v4
        with:
          name: ai-report
          path: exp4/report.md
      - name: Mark task PASSED and post report on Issue 1
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          gh issue comment 1 --repo ${{ github.repository }} --body "CI PASSED for commit ${{ github.sha }}"
          gh issue comment 1 --repo ${{ github.repository }} --body-file exp4/report.md

  failed:
    needs: test
    if: failure()
    runs-on: ubuntu-latest
    steps:
      - name: Mark task FAILED on Issue 1
        env:
          GH_TOKEN: ${{ github.token }}
        run: gh issue comment 1 --repo ${{ github.repository }} --body "CI FAILED for commit ${{ github.sha }}. Check the Actions tab."
```
⚠️ YAML uses **spaces, not tabs**. Keep the indentation exactly as shown.

## Step 6: Break it on purpose (FAILURE path)
The local pre-commit hook would block a broken script, so use `--no-verify` to skip it **only for this test**:
```bash
printf 'if [ true\n' > exp4/broken.sh
git add exp4/broken.sh
git commit -m "Test CI failure" --no-verify
git push
```
✅ In the **Actions** tab, **test** is red ❌, **report** is skipped, and **failed** runs.
✅ **Issue #1** has a comment "CI FAILED for commit ...".

## Step 7: Fix it (recovery)
```bash
git rm exp4/broken.sh
git commit -m "Remove broken script"
git push
```
✅ The pipeline is green again and Issue #1 gets a new "CI PASSED" comment and report.

---
**If push says "refusing to allow a Personal Access Token to create or update workflow":** the token does not have the **workflow** scope. Make a new token with **repo + workflow + read:org** (SETUP Step 3), then run:
```bash
echo "ghp_NEW_TOKEN" > ~/.github_token
rm -f ~/.git-credentials
git push        # username tejuthomass, password = new token
```

**If the report job says "AI not reachable":** the secret name must be exactly `GEMINI_API_KEY`. The pipeline still passes with the rule-based report.

**If the comment step fails with "Resource not accessible":** check that the `permissions:` block (`issues: write`) is in `ci.yml`.
